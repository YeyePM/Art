## 二、调用参数上必须做的两件事

1. **把思考压到最低档。** 原以为"关掉就行"，**实测（2026-10-08，T3）证明关不掉**：`thinking.type` 只认 `enabled`，传 `disabled` / `minimal` 都会被 `1210 该模型始终思考，不支持关闭思考` 拒掉。

   | 参数 | 结果 |
   | --- | --- |
   | `thinking: {type:'disabled'}` | ❌ 400 / 1210 |
   | `thinking: {type:'low'}` | ❌ 400 / 1210 |
   | `thinking: {type:'enabled'}` | ✅ 但仍思考 |
   | **`reasoning_effort: 'low'`** | ✅ **思考降到 24 tokens**（同一提示词：默认档 29842 输出 token / 思考 25774 / 266 秒；low 档 2785 / 思考 24 / 71 秒 —— **成本约 1/10**） |
   | `reasoning_effort: 'minimal'` | ❌ 只支持 low / high / max |

   **结论：固定写 `reasoning_effort: 'low'`**，已落地在 `app/api/src/ai/zhipuClient.js`。
2. **约束 JSON 输出。** 用 `response_format: {type:'json_object'}`；若该模型不吃这个参数（400 且提到 `response_format`）自动去掉再试一次。解析前**先剥掉可能出现的 ```json 包裹**。

**另有一条要写进代码**：该接口会**偶发**返回 `1301 内容审核拦截`（同一提示词时中时不中）。这属于可重试错误，重试一次通常就过，**不要当硬错误直接抛给前端**。

## 三、成本控制

- 每天只生成一次，生成后**立刻落库**，当天复用。
- 生成失败要有超时与重试，但**不要无限重试**。

## 四、事实纪律（本项目最大的风险在这）

- 图像辨识题的**作者 / 年代一律取博物馆元数据**（Met 的 `artistDisplayName`、`objectDate`），AI **只写风格依据与干扰项**。
  → 把幻觉风险最大的一环交给权威数据。
- 年代、作者、流派、作品名一旦不确定，宁可不写也不要编；有疑问在解析里标"存疑"。
- 难度基线写死在提示词里：**对标各大美院美术史考研真题**，否则默认出通识题（如"南北宗论"），对目标用户太浅。

## 五、生成今日 10 题的系统提示词（定稿，直接用）

变量只有两个：`{N}` 缺题数、`{元数据}` 图像辨识题的博物馆元数据。

```text
你是我的美术史复盘出题助手。我的背景：油画专业硕士在读，美术史功底远高于普通爱好者。

【任务】
生成 {N} 道题，补齐今天的每日 10 题。

【难度】
对标央美 / 国美 / 清美等院校美术史考研真题。严禁通识送分题
（如"南北宗论"、"文艺复兴三杰是谁"）。
难度档要拉开：基础 / 进阶 / 挑战 都要出现。

【配额与分布】
- 题型上限：开放论述 ≤ 1、名词解释 ≤ 2、图像辨识 ≤ 2，其余为客观题
- 中国美术史与外国美术史混合出现，不按时间线排序
- 覆盖范围：整个美术史，从史前到当代都要能出，不许集中在某一时期

【事实纪律（最重要，违反即作废）】
- 年代、作者、流派、作品名一旦不确定，宁可不写也不要编
- 有疑问直接在 explanation 里标注"存疑"，不要含糊过去
- 图像辨识题不许靠"看"去认作者和年代：作者与年代一律以随题给你的
  博物馆元数据为准，你只负责写风格依据和三个干扰项
  （元数据：{元数据}）
- 开放论述题优先取"创作实践"方向（笔触该不该被看见、完成感从哪来、
  写生与重构的关系等），要有争议点，不给标准答案

【输出】
只输出一个 JSON 对象。不要解释、不要客套话、不要用 markdown 代码块包裹：

{
  "hook": "一句不剧透的引子，20 字以内，用于当天桌面通知。严禁出现'你还没做''还差几题''连续要断了'这类催办话",
  "questions": [
    {
      "type": "objective | term | image | essay",
      "stem": "题干",
      "options": ["A ...", "B ...", "C ...", "D ..."],
      "answer": "参考答案；objective / image 给正确选项；essay 写'参考思路'",
      "explanation": "解析：这道题的考点是什么 + 最容易错在哪",
      "difficulty": "基础 | 进阶 | 挑战",
      "tags": ["宋", "文人画"]
    }
  ]
}

objective 与 image 必须给 4 个 options；term 与 essay 的 options 填 null。
```

**顶层 `hook` 字段是推送用的**（见 [04-核心规则.md](./04-核心规则.md) 推送一节）：随生成今日 10 题顺手输出，**不额外调 AI**，落到 `daily_sessions.hook`。

## 七、实测记录（2026-10-08）

**看图（第一阶段）**：拿 `design/img/q-image.jpg`（82 KB）实跑一次：

- 正确说出 **维米尔《持水壶的年轻女子》**、约 **1662 年**、**大都会艺术博物馆**；"光线从**左侧**的窗户射入"；画面细节全部对得上。
- 四项判读全部命中，**无幻觉**。
- 用量：输入 505 tokens、输出 870 tokens（其中思考 539）→ 约 0.003 元。

**出题（T3 落地阶段）**：按第五节定稿提示词生成当日 10 题：

- 一次生成 10 道，题型分布与 `needMoreByType` 完全一致；图像辨识题的作者 / 年代与传来的博物馆元数据一致，**无编造**。
- **模型会多给**：两次实跑都给了 11 道（图像辨识 3 道，超 1 道）。提示词约束不住，**必须在落库前按题型上限硬裁**（`services/dailyGeneration.js` 的 `trimToQuota()`）。
- 用量（low 档）：输入 779 tokens、输出 3450～3780 tokens（其中思考 9～553）→ 约 **0.5 分钱**，耗时 37～93 秒。
- 原样重插一遍：10 道**全部**被 `questions.fingerprint` 的 UNIQUE 约束挡下。
- 思考档的横向对比见第二节第 1 条。
