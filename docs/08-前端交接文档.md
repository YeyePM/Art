## 3. 要交付的东西

### 3.1 页面结构（只有两层）

```
主界面（概览 + 导航）
   ├─→ 今日页（10 题 + 本周一批）
   └─→ 学习进度页
```

**导航硬要求**：任何二级页都必须有回主界面的入口，不允许"进去了出不来"；层级只有**两层**（主界面 ⇄ 二级页），二级页的返回一律回主界面，不做"回上一层"。

### 3.2 主界面（M7 / T8）

- 三个概览卡**横排**：① 今日的题 ② 学习进度 ③ 本周一批
- **每张卡右侧 38% 放一张名画**（本地图），填住文字旁的空；**卡展开时图淡出、文字铺满整卡**
- **只显示粗略结论，不给正文**（不出现题干、不出现摘录原文、不出现参考答案）
  - 今日的题：进度 6/10（可带估时）
  - 学习进度：连续 6 天 · 正确率 78%
  - 本周一批：画名 + 摘录 + 一个开放问题（一句话摘要）
- **两级进入**：第一下点板块 → **就地展开预览 +〔进入〕**；第二下才路由到内容页。**第一下是"看"，第二下才是"进"**
- **鼠标左右移动**驱动整排卡片横移；**回车**直接落到今日页
- **当天第二次打开跳过主界面**，直接进今日页（用 `localStorage` 记"今天已打开过"，键带日期）
- 设计稿里三张卡的图：`design/img/home-01-progress.jpg`、`home-02-quiz.jpg`、`home-03-weekly.jpg`

## 4. 接口（前端只用 1–11；12/13 属 v0.2 不做；14 是后端验收用）

> 完整字段与规则见 [specs/01-接口契约.md](../specs/01-接口契约.md)，这里只列前端要用的部分。

| # | 方法 | 路径 | 用途 |
| --- | --- | --- | --- |
| 1 | GET | `/api/health` | 探活 |
| 2 | GET | `/api/today` | 今日 10 题 + 进度 + 是否打卡 |
| 3 | POST | `/api/answers` | 交卷、拿判定与解析 |
| 4 | GET | `/api/stats` | 连续 / 最长 / 总天数 / 正确率 + 打卡日历 |
| 5 | GET | `/api/weekly` | 本周一批（画 / 摘录 / 开放问题） |
| 6 | POST | `/api/artworks/note` | 给画写一句 |
| 7 | POST | `/api/open-questions/answer` | 回答开放问题 |
| 8 | POST | `/api/flag` | 标记问题 |
| 9 | GET | `/api/images/{filename}` | 取本地缓存图（图片二进制） |
| 10 | GET | `/api/home` | 主界面三个概览卡的汇总 |

### 4.1 `GET /api/today`

```json
{
  "date": "2026-10-08",
  "questions": [ /* 见下 */ ],
  "progress": { "done": 6, "total": 10 },
  "checked_in": false,
  "notice": null
}
```

`questions[]` 单项：

```json
{
  "id": 12,
  "type": "objective",
  "stem": "题干文字",
  "options": ["A 选项", "B 选项", "C 选项", "D 选项"],
  "difficulty": "进阶",
  "image_url": "/api/images/met-437881.jpg",
  "is_review": false,
  "tags": ["宋", "文人画"]
}
```

- `type` 四值：`objective`（客观）/ `term`（名词解释）/ `image`（图像辨识）/ `essay`（开放论述）
- `term` 与 `essay` 的 `options` 为 `null`
- `difficulty` ∈ `基础 | 进阶 | 挑战`
- `image_url` 只有图像辨识题有，**可能为 `null`**（图没下好），前端要容错
- **`/api/today` 绝不返回答案与解析**，前端别指望提前拿到

### 4.2 `POST /api/answers`

请求：`{ "question_id": 12, "user_answer": "B", "self_grade": true }`

- `question_id` 整数必填；`user_answer` **四种题型都必填**（先交卷才换得到判定与参考答案）
- `self_grade` 只用于**改判**，只对名词 / 论述有效；**客观题 / 图像辨识题带了它返回 400**

响应：

```json
{
  "correct": true,
  "explanation": "解析文字",
  "reference_answer": "B",
  "ai_comment": "AI 的点评（主观题才有，否则 null）",
  "ai_errors": ["事实性硬错误，每条一句"],
  "next_review_at": null
}
```

- `correct` 为 `null` 表示**没判上**（AI 调不通），前端**让用户自己定对错**，不要报错
- `reference_answer`：客观 / 图像辨识是正确选项字母；名词 / 论述是参考答案原文
- `next_review_at`：下次复习日期（`YYYY-MM-DD`）或 `null`，只用来显示"下次复习：X 月 X 日"
- 同一题同一天**重复提交是幂等的**（不重调 AI、不推进间隔）；**改判（带 `self_grade`）那次不算重复**，会覆盖判定

### 4.3 `GET /api/stats`

```json
{
  "current_streak": 3,
  "longest_streak": 7,
  "total_days": 20,
  "accuracy": {
    "overall": 0.78,
    "by_type": { "objective": 0.9, "term": 0.6, "image": 0.8, "essay": null }
  },
  "calendar": [
    { "date": "2026-09-09", "checked_in": false },
    { "date": "2026-10-08", "checked_in": true }
  ]
}
```

- `accuracy.overall` / `by_type.*` 是 **0～1 的两位小数**；没作答过是 `null` → 显示"—"而不是 0%
- `by_type` 四种键**一定齐全**
- `calendar`：**最近 30 天（含今天）升序、一天不缺**，只标 `checked_in`
- 不接受任何参数（别传 `date`）

### 4.4 `GET /api/weekly`

```json
{
  "batch_id": 3,
  "starts_on": "2026-10-08",
  "ends_on": "2026-10-14",
  "artwork": {
    "id": 7, "title": "持水壶的年轻女子", "artist": "约翰内斯·维米尔",
    "period": "1662", "school": null,
    "image_url": "/api/images/met-437881.jpg",
    "note": { "content": "留白很狠", "is_empty": false }
  },
  "excerpt": {
    "id": 2, "book_title": "历代名画记", "chapter": "卷一 论画六法",
    "source_text": "……原文……", "contact_line": "一句触点"
  },
  "open_question": {
    "id": 2, "stem": "完成感究竟从哪里来？",
    "reference_thoughts": "可从笔触与停笔的判断切入。",
    "user_answer": "我自己的回答……"
  }
}
```

- `artwork.image_url` 一律是本机缓存路径，**没缓存到图时为 `null`**（画照留，界面显示无图）
- `artwork.note`：从没写过是 `null`；写过空内容是 `{content: null, is_empty: true}`（留空也算记了一笔）
- `open_question.user_answer`：没写过是 `null`
- **滚动 7 天**：`ends_on = starts_on + 6 天`；未满 7 天再打开原样返回

### 4.5 三个写接口

| 接口 | 请求 | 响应 |
| --- | --- | --- |
| `POST /api/artworks/note` | `{artwork_id, content}`（空内容也记） | `{ok: true}` |
| `POST /api/open-questions/answer` | `{open_question_id, content}`（留空不算答过） | `{ok: true}` |
| `POST /api/flag` | `{target_type, target_id, note?}` | `{ok: true}` |

- `target_type` ∈ `question` / `artwork` / `excerpt` / `open_question` / `fragment`，其余 400
- `target_id` 必须正整数，否则 400；`note` 可选
- 参数错误一律 `400`，响应体 `{"error": "中文说明"}`

### 4.6 `GET /api/home`

```json
{
  "date": "2026-10-08",
  "today_progress": { "done": 6, "total": 10 },
  "stats": { "current_streak": 6, "accuracy": 0.78 },
  "weekly_summary": {
    "batch_id": 3, "starts_on": "2026-10-08", "ends_on": "2026-10-14",
    "artwork_title": "持水壶的年轻女子", "excerpt_book": "历代名画记",
    "has_open_question": true
  },
  "notice": null
}
```

- 只给**粗略结论**，**不给正文**（不含摘录原文、题干、参考答案）；没有批次时 `weekly_summary` 为 `null`
- **副作用**：主界面是"当天内容就绪"的入口——第一次打开会按需备好当天题单与本周批次，之后进今日页 / 本周一批秒开；幂等，一天一次

## 6. 交互规范

### 6.1 主界面：鼠标左右移动驱动横排平移（核心）

- 监听 `pointermove`，把光标横坐标映射成整排的位移：`x = clamp(clientX / innerWidth, 0, 1)`，`目标位移 = -x * panMax`（`panMax = deck.scrollWidth - viewport.clientWidth`）
- **缓动追赶，不是硬跟手**：`requestAnimationFrame` 里 `cur += (aim - cur) * 0.14`，用 `translate3d` 位移
- 设计稿还有一条底部进度条随鼠标位置变化（`width: x*100%`），可保留作反馈
- 主界面盖满整屏时**拦掉滚轮**（`wheel` 里 `preventDefault`），别把下层页面滚走
- **回车**：焦点不在 `input/textarea` 时按下 → 直接落到今日页（若就地展开的是"学习进度"，回车进进度页）

### 6.2 两级进入

- 第一下点区块 → **就地展开**（预览 +〔进入〕按钮），图淡出、文字铺满
- 第二下（再点该卡，或点〔进入〕）→ 路由到内容页

### 6.3 加载与失败态（贯穿全局）

- **`/api/today` 是同步阻塞的**：首次打开后端要凑齐 10 题（可能真调 AI，几十秒），前端**全程 loading、不要轮询**；当天第二次因已落库是秒开
- **主观题提交要等十几秒**（名词 / 论述后端同步等一次 AI 判分），前端**必须给 loading，不要轮询**，别当成接口卡死
- **`notice` 非 `null`** 时：那是给人看的一句话提示（如 AI 暂时不可用），**照常显示手头的题，不要白屏**；题可能不足 10 道
- **接口失败**：显示明确提示 + 重试按钮（把后端停了再打开页面，要看到提示而不是白屏）
- 加载期用**骨架屏**

## 8. 硬约束与不要做的事

### 8.1 必须守住（做错会返工）

1. **`/api/today` 绝不返回答案和解析**——答案只在交卷后（`/api/answers`）给，前端别指望提前拿到
2. `/api/today` 与主观题提交都是**同步阻塞**——**全程 loading、不要轮询**
3. **`correct` 为 `null`** 表示 AI 没判上——界面**让用户自己定**对错，不要报错
4. **改判**：带 `self_grade` 再提交一次同一题即为改判；**客观题不接受 `self_grade`**
5. **`notice` 非 `null`** 时照常显示手头的题，**不要白屏**
6. **图片走 `/api/images/{filename}`**，直接用 `image_url` 即可，断网也能显示
7. **前端不算连续天数、不算遗忘曲线、不自己判分、不自己算间隔**——一律读 `/api/stats` 与 `/api/answers`，否则数字会跟后端对不上
8. **文案硬防线**：界面上不出现"你还没做 / 还差几题 / 连续要断了"这类催办话
9. **前端不直连 AI、不读数据库文件**，一律走后端接口
10. **二级页必有「← 返回主界面」**，层级只做两层

### 8.2 不要做

- 进度页**不做趋势图、不做标签维度分析**，页面上找不到"薄弱点"字样
- v0.1 **不做**碎片上传（接口 12/13 属 v0.2）
- 前端**不做**复习打卡逻辑

## 9. 工程约定

### 9.1 目录（前端部分）

```
app/web/
├─ src/
│   ├─ pages/        今日页 / 主界面 / 学习进度页
│   ├─ components/   题目卡片、统计条、周批次块、返回胶囊、碎片圆钮…
│   └─ api/          接口调用封装（一处包 fetch，统一 loading / 错误）
├─ public/           静态资源（T8 的三张概览卡名画可放这，或引用 design/img）
├─ mock/today.json   假数据（仅开发期）
└─ vite.config.ts    端口 + /api 代理到 5178
```

- **`app/web/mock/today.json`**：按 4.1 的结构造 10 道题，**四种题型都要有、至少 1 道 `is_review: true`**；后端接口稳了再切数据源
- 根 `package.json` 的 `workspaces` 要**加上 `app/web`**，并加一条 `dev:web` 脚本

### 9.2 双击脚本放 `测试\web\`

- 命名 `<两位序号>-<里程碑>-<名字>.bat`
- 脚本内用 `cd /d "%~dp0..\.."` 回项目根，**放在 `测试\web\` 这一层别挪**（挪了找不到项目根）
- 内容**全 ASCII**（`rem` 注释也别写中文，cmd 会拆错报 `'em' is not recognized`）
- 参考后端已有的 `测试\api\01~13`（同一套写法）

### 9.3 三条代码组织硬约束

1. AI 调用只在 `app/api/src/ai/`，前端碰不到
2. 业务逻辑只在 `app/api/src/services/`，接口层不写逻辑
3. `data/` 与 `.env` 不进版本库；`data/` 要能整体复制搬走

## 10. 已知的坑（别再踩）

| 坑 | 现象 | 结论 |
| --- | --- | --- |
| 打开根路径是白的 | `http://localhost:5178/` 无页面 | 后端**只有 JSON 接口**，这是正常的；页面由前端提供 |
| 推送地址指错 | 点桌面通知落到 5178 根路径（404 JSON） | 开发期前端在 5173，需把后端 `config.push.url` 临时改成 `http://localhost:5173/` |
| 前端 dev 端口 | 直接占用 5178 会和后端撞 | Vite 用 5173 + `/api` 代理到 5178 |
| 内网图源 | `trae-api-cn.../text_to_image` 只返回灰底占位图 | **不要拿它当图源**；前端只用后端 `/api/images/` 与 `design/img/` 里的真图 |
| Node 不在 PATH | 终端敲 `node` / `npm` 报"不是内部或外部命令" | 本机 Node 在 `E:\New Folder\nodejs`，已加进用户 PATH；**已开的终端要重开才生效** |
| Shell 输出的 CLIXML | 每条命令都带一段"profile 脚本被禁用"的报错 | 是环境噪声，命令本身正常，**忽略** |
| 双击 bat 没反应 | 在 Trae 文件树里双击会当文本在编辑器打开 | 要在**文件资源管理器**里双击（右键 → 在文件资源管理器中显示） |
