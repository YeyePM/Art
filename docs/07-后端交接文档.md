## 1. 一分钟上手

在**项目根目录**执行（不是 `app/api/`）：

```bash
npm install        # 首次安装依赖（.npmrc 已配 better-sqlite3 国内镜像）
npm run init:db    # 建表，幂等，重复执行不会清数据
npm run dev        # 起后端 → http://localhost:5178

npm run seed       # 开发期：塞 30 道假题进库（替代 AI），--reset 重塞 / --clear 清空
npm run preview    # 看结果：把今天会出的 10 道题按顺序打印出来（只读，不改数据）
npm run verify:t2  # 开发期：组题规则自测（会清空题库再重塞，只在开发期跑）
npm run verify:t3  # 开发期：真调一次智谱生成今日 10 题 + 自检（会花钱，约 0.5 分钱）
npm run verify:t4  # 开发期：起真实服务打一次 /api/today + 自检（会花钱，约 0.5 分钱）
npm run verify:t5  # 开发期：POST /api/answers 自测（**会真调 2 次 AI、约 0.1 分钱**；不动你现有题库，跑完自动清场）
npm run verify:t6  # 开发期：错题队列与遗忘曲线自测（**不花钱、不动你现有题库**，跑完自动清场）
npm run verify:t7  # 开发期：打卡与统计自测（**不花钱、不动你现有题库与作答**，跑完自动清场）
npm run verify:t8  # 开发期：每周一批自测（**含 1 次真实 AI 生成、约 0.05 分钱**，不动你现有批次）
npm run verify:t9  # 开发期：图片抓取与本地缓存自测（**不花钱、需联网**，会留下 1 张 data/images/ 缓存图）
npm run verify:t10 # 开发期：标记问题与 AI 兜底自测（**不花钱、不联网**，临时清空进程内 AI Key 模拟"AI 挂了"，跑完自动清场）
npm run verify:t11 # 开发期：主界面概览与打卡日历自测（规则段不花钱不联网；末尾真实比对四个接口的数字，若今天题单还没生成过会顺手生成一次）
npm run verify:t12 # 开发期：推送自测（**不花钱、不联网、不弹通知**：硬防线 / 时间窗 / 幂等 / 通知失败降级；末尾另真弹一条演示通知）
npm run autostart  # M8：把后端写进 Windows「启动」文件夹（开机自启）并立即在后台起一份；`autostart:remove` 可取消
npm run backfill:images  # 把历史图像辨识题缺的图下到本机并回填（幂等，可反复跑）
```

**不想开终端**：验收脚本统一收在 **`测试\api\`**，命名 `<两位序号>-<里程碑>-<原名>.bat`（序号按里程碑先后排 01~13）。脚本里用 `cd /d "%~dp0..\.."` 回项目根，所以**必须放在 `测试\api\` 这一层，别往别处挪**（挪了会找不到项目根）。按顺序双击：`01-M1-看今天题目.bat`（看当天 10 道题）、`02-M1-生成今天的题目.bat`（真调 AI 生成一批并自检）、`03-M1-验收今日接口.bat`（走真实接口跑一遍今日会话）、`04-M2-验收判分接口.bat`（跑一遍判分）、`05-M3-验收复习曲线.bat`（走一遍 1→3→7→15）、`06-M4-验收打卡统计.bat`（走一遍打卡与连续天数）、`07-M5-验收每周一批.bat`（走一遍滚动 7 天 + 真生成一批）、`08-M5-验收图片缓存.bat`（把一张画下到本机再取回来）、`09-M5-回填画作图片.bat`（补历史缺图，幂等，可反复跑）、`10-M6-验收兜底.bat`（走一遍标记与"AI 挂了"降级）、`11-M7-验收主界面接口.bat`（比对主界面与今日页 / 学习进度页的数字 + 打卡日历）、`12-M8-验收推送.bat`（走一遍推送的四道关 + 末尾真弹一条通知）、`13-M8-开机自启并启动后端.bat`（装开机自启并立即在后台起一份后端）。十三者都会打印在一个黑窗口里，看完按任意键关掉。

验收点：浏览器打开 `http://localhost:5178/api/health`，返回 `{"ok":true}`。

## 4. 数据库

**15 张表**（`questions` / `tags` / `question_tags` / `answers` / `review_queue` / `daily_sessions` / `checkins` / `artworks` / `artwork_notes` / `excerpts` / `open_questions` / `weekly_batches` / `flagged_items` / `push_log` / `fragments`）

- **`fragments` 属 v0.2 但已建好**，避免以后改结构。
- **`notes` 和 `settings` 明确不建**：`notes` 留到 v0.2；`settings` 的参数写在 `src/config.js`。

**存数据的约定（改数据前先看这条）**

| 约定 | 说明 |
| --- | --- |
| 日期 | `TEXT 'YYYY-MM-DD'` |
| 时间戳 | `TEXT 'YYYY-MM-DD HH:MM:SS'`，取 `datetime('now','localtime')` |
| JSON 字段 | `questions.options`、`daily_sessions.question_ids`、`fragments.ai_tags` 都存 **JSON 字符串**，读出要 parse |
| 去重 | `questions.fingerprint` 有 **UNIQUE 约束**，重复插入会直接报错，靠它挡重复题 |
| 复习 | `review_queue.interval_days` 只允许 1/3/7/15（CHECK 约束）；`status='done'` 即出队 |
| 复习出队 | **走完全程才出队**：1→3→7→15，15 天节点答对才出队（等价连对 4 次） |
| 打卡 | 一天最多一条（`checkins.date` 有 UNIQUE 约束，用 `INSERT OR IGNORE` 挡重复）；**完成当天题单才写**，且**从不回填过去**；顺手把 `daily_sessions.checked_in` / `done_count` 更新掉（`/api/today` 的 `checked_in` 就读这里） |
| 题目固定 | 当天题写在 `daily_sessions.question_ids`，同一天不再重新生成 |
| 主观题判定 | `answers.is_correct` 是**最终判定**；`is_self_graded=1` 表示最终判定由用户给（改判）；`ai_correct` / `ai_comment` / `ai_errors` 是 AI 的原始判定、点评、抓到的硬错误，**改判后不清空**（留底，以后能看"AI 判的跟你判的差多少"） |
| 加列 | `CREATE TABLE IF NOT EXISTS` **不会给老表加列**，旧库升级靠 `db/index.js` 里的 `migrate()`（PRAGMA table_info + ALTER TABLE ADD COLUMN，只加可空列） |

已实现 **6 个接口 + 4 个写入口 + 1 个静态图**：`GET /api/health`、`GET /api/today`（返回 `{date, questions[], progress:{done,total}, checked_in, notice}`；`notice` 是 M6 加的，AI 挂了时给人话、正常为 `null`）、**`POST /api/answers`**（返回 `{correct, explanation, reference_answer, ai_comment, ai_errors, next_review_at}`）、**`GET /api/stats`**（返回 `{current_streak, longest_streak, total_days, accuracy:{overall, by_type}, calendar[]}`；`calendar` 是 M7 加的 30 天打卡日历）、**`GET /api/weekly`**（返回 `{batch_id, starts_on, ends_on, artwork, excerpt, open_question}`）、**`GET /api/home`**（返回 `{date, today_progress, stats, weekly_summary, notice}`，三个板块直接复用各自页面的函数，数字必然一致）；写入口 `POST /api/artworks/note`、`POST /api/open-questions/answer`、**`POST /api/flag`**、**`POST /api/push/test`**（T12 加：手动触发一次推送，带 `at` 走完整判断、不带则立即发，返回 `{ok:true, ...}`）；静态图 `GET /api/images/{filename}`（由 `express.static(data/images)` 提供，**断网也能看图**）。完整 14 个接口的契约见 [specs/01-接口契约.md](../specs/01-接口契约.md)（勿另起一份，两边会分叉），字段细节见它第一节、「一之二」～「一之七」。

`/api/today` 是**同步阻塞**的：当天第一次打开会当场调 AI 补题（约 40～90 秒），前端全程显示 loading；当天第二次打开读库，秒开。**不加 `generating` 之类字段，不做轮询。**

**一条红线**：`/api/today` **绝不返回答案与解析**，只在 `POST /api/answers` 的响应里给——包括主观题的参考答案。
- `/api/today` 走 `db/questions.js` 的 `getForDisplay()`，SQL 里就没有 `answer` / `explanation`；
- `/api/answers` 走 `getWithAnswer()`，这是唯一带答案的路。**两条路不许混，别往 getForDisplay 上加答案字段。**

## 7. 组题规则与后续任务（M1）

**T2 已定稿：组题规则**（`src/services/questionPicker.js`）

当日 10 题的题型构成是固定的：**论述 1 + 名词 2 + 图像辨识 2 + 客观 5**。组装顺序：

1. ① 昨日未完成题（**顺序保留，排在最前**）→ ② 到期复习题（`next_review_on <= 今天`）→ ③ 从题库补足。
2. 补足时按上面的构成排一张计划表，把稀缺题型**均匀插开**，不会出现"前 5 道全是名词"。
3. 中外混合：每一步优先从当前偏少的一侧取，结果一中一外交替。
4. 候选顺序按**日期做种子打乱**：同一天两次调用结果一致，换一天会变，且不会按时间线排。

两条边界：**配额永不膨胀**（凑够 10 就停，不是再发 10 道）；**题库不够时如实报缺**，缺哪些题型、各缺几道由 `needMoreByType` 给出。

调用契约：

```js
pickDailyQuestions({ carryOverIds, dueReviewIds, date })
// → { questionIds, needMore, needMoreByType, counts, origins }
```

- `needMore === 0` 时 T3 完全不用调 AI。
- **`carryOverIds` 必须由 T4 显式传入**（T4 自己从昨日 `daily_sessions` 算出未完成的题）。组题层**故意不扫** `daily_sessions`，别在两边各实现一次。

**T3 AI 生成与落库（已跑通）**

调用契约（`src/services/dailyGeneration.js`）：

```js
await generateAndStoreDailyQuestions({ date, needMore, needMoreByType, artworks })
// → { hook, insertedIds, inserted, skipped, requested, shortfall, reused, usage }
```

- `date`：按 Asia/Shanghai 的 `YYYY-MM-DD`，只用来做"当天不二次调 AI"的记忆键。
- `artworks`：图像辨识题的博物馆元数据数组，形如
  `{ title, artist, period, school, sourceLibrary, externalId }`。
  第 1 道图像辨识题配第 1 件作品。**作者 / 年代一律以它为准**，AI 只写风格依据和 3 个干扰项。
- 返回的 `hook` **要由 T4 写进 `daily_sessions.hook`**（推送用）；生成层**故意不碰** `daily_sessions`。
- `needMore === 0` 时直接返回，**完全不调 AI**。

写死的规则：

- 按 `needMoreByType` 分配题型，**总量等于 `needMore`**；数量不足时最多再补一轮（`MAX_ROUNDS = 2`），不无限重试。
- **模型会多给，落库前必须按配额硬裁**：实测两次要 10 道都给了 11 道（图像辨识 3 道，超 1 道）。提示词约束不住，`trimToQuota()` 按题型上限裁掉多余的，返回里的 `generatedRaw` 是 AI 实际给的数、`inserted` 是通过配额的数。
- 图像辨识题会顺手写一条 `artworks` 记录并把 `questions.artwork_id` 挂上（`image_path` 留空，**等 M5 的图片缓存回填**）。
- 去重：`questions.fingerprint` 的 UNIQUE 约束；另外进程内按 `date` 记一份结果，**补齐了才记**，同一天再调直接复用，不再花钱。
- 不合格的题（缺题干 / 缺答案 / 客观题选项不足 4 个）在归一化时直接丢掉。

**降级方案（AI 卡住时不影响推进）**：用 `npm run seed` 塞的 30 道假题顶上，先把链路跑通，之后只替换 `generateQuestions` 那一处。

**T4 今日会话接口（已验收）**

调用契约（`src/services/todaySession.js`）：

```js
await buildTodaySession({ date, artworks })
// → { date, questionIds, hook, checkedIn, generated, reused, shortfall }

await getTodayView({ date })
// → { date, questions[], progress:{done,total}, checked_in }   ← 直接就是接口返回的形状
```

- **幂等**：当天已写过 `daily_sessions` 就直接读库返回（`reused: true`），**不再调 AI、不再花钱**。这就是"当天不二次调 AI"的落地方式。
- `carryOverIds` 由这一层算：昨日 `daily_sessions.question_ids` 减去昨日 `answers` 里已作答的（`db/answers.js` 的 `filterUnanswered`）。**组题层故意不扫 `daily_sessions`，别在两边各实现一次。**
- 组装顺序：① 昨日未完成题（顺序保留）→ ② 到期复习题（`next_review_on <= 今天`）→ ③ 缺的调 AI。**配额永不膨胀**（凑够 10 就停）。
- `hook`（AI 顺手给的通知文案）在这里写进 `daily_sessions.hook`；生成层故意不碰这张表。
- `is_review` 不落库，读接口时用 `review_queue` 里还活着的题目 id 现算——同一天第二次打开也标得对。
- `progress.done` 由 `answers` 现算（`session_date = 今天`），不依赖 `daily_sessions.done_count`。`done_count` 留给 M4 打卡用。
- `image_url` 由 `questions.image_path` 拼出来；M5 之前一直是 `null`。

**T5 判分接口（已验收）**

调用契约（`src/services/grading.js`，**`submitAnswer` 是 async**）：

```js
await submitAnswer({ questionId, userAnswer, selfGrade, date })
// → { correct, explanation, reference_answer, ai_comment, ai_errors, next_review_at }
//    AI 调不通时：{ correct: null, …, ai_failed: true }，且不落库
```

分支表（**写在文件头注释里，这是最容易改错的地方**）：

| 情形 | 怎么走 |
| --- | --- |
| 带了 `self_grade` | **改判**：覆盖 `is_correct`、置 `is_self_graded=1`，AI 原始判定留在 `ai_correct` |
| 已有记录、没带 `self_grade` | **幂等返回**，**不重新调 AI、不再花钱** |
| 客观题 / 图像辨识题 | 拿 `userAnswer` 跟库里 `answer` 比，**一次判完** |
| 名词解释 / 论述题 | **调一次 AI 判**（十几秒）→ 判完即落库 |

- **客观题 / 图像辨识题不交给 AI**：答案是确定的选项字母，直接比零延迟零成本，AI 反而更慢还可能判飘。两边都过 `normalizeChoice()` 归一到选项字母——前端传 `"B"` / `"b"` / `"B."` / 整条选项文字都认；AI 偶发把答案写成整条选项文字，也认。认不出来（脏输入）判为不通过，**不抛错**。
- **名词解释 / 论述题由 AI 判**（`ai/gradeAnswer.js` + `prompts/grade-answer.txt`）：不要求"跟参考答案一致"（论述题本来就没有标准答案），AI 的判据是立场是否明确、有没有具体作品或史实支撑、论证是否自洽；**事实性硬错误（作者 / 年代 / 流派 / 归属 / 地域搞错）一律判 false 并写进 `ai_errors`**。判完把 `ai_correct` / `ai_comment` / `ai_errors` 一起落库。
  - 自测实录：作答里故意埋了 4 处硬错误（"德加是未来主义""《持水壶的年轻女子》是德加的""画于文艺复兴时期""几何化运动感"），GLM-5.3-Flash **全抓出来了**，判定 false。
  - 实测每题一次 AI 十几秒、约 0.05 分钱。
- **用户可改判**（"AI 判错了我再给它反馈"）：拿到判定后不认时，**再提交一次、带上 `self_grade`**，最终判定就听用户的。不需要新接口，复用这一个。改判**只覆盖 `answers.is_correct`**，AI 的原始判定与点评都留着。
- **AI 调不通时降级**（超时 / 内容审核拦截）：返回 `correct: null` + `ai_failed: true`，**不落库**；用户带 `self_grade` 再提交一次即可（走的就是改判这条分支）。**所以改判分支天然兼任兜底，不用另写代码。**
- **四种题型都必须带 `user_answer`**：先交卷，才换得到判定与参考答案。
- `reference_answer`：客观题是正确选项字母，主观题是参考答案原文。
- `next_review_at`：**由 T6 复习队列给出**（`services/reviewQueue.js`）——答错 → 明天；复习答对 → 下一节点（1→3→7→15）；**走完全程出队、以及本来就没进过队的题 → `null`**。
- `session_date` 记的是**作答当天**，不是这道题原本属于哪天（specs/04 第三节：昨天没做完的今天补做，计入今天的额度）。
- **同一题同一天重复提交是幂等的**（双击 / 断网重试）：直接返回首次判定（含当时的点评），不重新调 AI、不再写第二条 `answers`，**也不会把复习间隔再往前推一格**。**带 `self_grade` 的那次不算重复提交**（复习队列按新判定重算一次）。
- 参数错误统一抛 `status: 400`，由 `app.js` 的错误中间件照 `err.status` 出状态码；`500` 才算服务内部错误。**客观题带了 `self_grade` 也是 400**（那两类由系统直接判，不给改）。

**T6 复习队列与遗忘曲线（已验收）**

调用契约（`src/services/reviewQueue.js`）：

```js
applyVerdictToReviewQueue({ questionId, correct, date })   // → 下次复习日 'YYYY-MM-DD' 或 null
getNextReviewOn(questionId)                                // → 还活着的队列项的下次复习日，否则 null
```

- `date` 是**判定发生的那天**（作答当天），由调用方给——正因为它是参数，自测才能在一天内把 1→3→7→15 走完，不用改系统日期。
- 触发点**只有一个**：`grading.js` 里"最终判定写下的那一刻"。谁都不许在别处再调一次。

分支表（**写在文件头注释里**）：

| 情形 | 怎么办 |
| --- | --- |
| 答错，已在队里 | 间隔**退回 1 天**，下次复习日 = 明天；`first_wrong_on` 不抹 |
| 答错，不在队里 | **入队**（间隔 1 天，下次复习日 = 明天） |
| 答对，没进过队 | **什么都不做**（跟复习无关）→ 返回 null |
| 答对，今天才入队 | **删掉那条**（AI 判错、当天改判成对）→ 返回 null |
| 答对，还没到 15 天 | **推进一格**（1→3→7→15） |
| 答对，已在 15 天节点 | **出队**（`status='done'`，记录留着） |

两条不许改错的边界：

- **幂等返回那条路不许调** `applyVerdictToReviewQueue`（只调 `getNextReviewOn` 读一下结果）——否则同一个判定会被应用两次，间隔白推一格。
- **改判要跟着改队**：改判走的是同一个函数，最终判定是什么，队列就按什么算。

**T7 打卡与统计（已验收）**

调用契约（`src/services/stats.js`）：

```js
maybeCheckIn({ date })   // → 这一次是否"新打出"了一张卡；做完当天题单才成立，幂等
getStats({ date })       // → { current_streak, longest_streak, total_days, accuracy:{overall, by_type} }
// 两个纯函数专供自测喂假日期：
computeCurrentStreak(dates, today) / computeLongestStreak(dates)
```

- 触发点：`grading.js` 里**真的写下了作答**的三个分支（客观题比完、主观题 AI 判完、AI 没判上时用户自己定）各调一次 `maybeCheckIn({date})`。幂等返回那条路不调。
- **"完成 10 题"落成"做完当天题单"**：正常那天就是 10 道；AI 没补齐（题单不足 10）时做完题单也算，否则那道短题单的日子永远打不了卡、连续天数会无故断掉。
- **从不回填过去**：只给传进来的那一天写打卡——这就是"被耽误的那一天不补记"。
- **连续三口径**：`current_streak` 要求最后一次打卡是**今天或昨天**，否则归零（今天还没过完，昨天仍算活着）；`longest_streak` / `total_days` 读全表，**永不清零**。
- `getStats` **不接受 `date` 参数**（日期一律后端按 Asia/Shanghai 算）；自测靠直接调服务层传假日期。
- 正确率 `0～1 两位小数`；`by_type` 四种题型键一定齐全，没作答过的是 `null`（前端显示"—"）。

## 8. 已知的坑（别再踩一遍）

| 坑 | 现象 | 结论 |
| --- | --- | --- |
| **智谱思考关不掉** | 传 `thinking:{type:'disabled'}`（或 `'low'` / `reasoning_effort:'minimal'`）报 `400 / 1210 该模型始终思考，不支持关闭思考` | `glm-5.3-flash` 只能调档，不能关。**用 `reasoning_effort:'low'`**：同一提示词默认档 29842 输出 token（思考 25774）/ 266 秒，low 档 2785（思考 24）/ 71 秒，**成本约 1/10**。已写死在 `zhipuClient.js`，别再改回 `thinking` |
