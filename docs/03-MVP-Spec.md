## 0. 这份 spec 怎么用

- **PRD 是"终局长什么样"，这份 spec 是"第一个能用的版本长什么样"**。
- 判断标准只有一条：**能不能验证"这个习惯立得住"**。凡是第一版不需要的，一律砍。
- 已确认的取舍：**内容全要（刷题 + 画 + 摘录 + 开放问题），但界面只要一页**。理由是"每周一批"本质是一个功能（共用一次生成、共用今日页一个区块），全保留的边际成本很低。

## 1. MVP 要验证什么

### 要验证的假设

> 我们相信，**把"每日 10 题"和"每周一批内容"放进同一个每日页面**，能让"复盘美术史"从一个愿望变成每天自动发生的动作。因为当前的问题不是没兴趣，而是**没内容、没节奏、没机制**。

### 成功指标（与 PRD 第 6 节一致）

| 类型 | 指标 | 目标 |
| --- | --- | --- |
| **主** | 每周至少 3 天完成 10 题的周数占比 | ≥ 70%（上线后第 2 个月起，观察 8 周） |
| 次 | 单日完成时长 | ≤ 15 分钟 |
| 次 | 错题重推正确率 | ≥ 60% |
| 次 | 每周画作"已写"比例 | ≥ 70% |
| 护栏 | "今天不想打开"的次数 | 每周 ≥ 3 次即必须减量 |

### 两个信号必须分开记（重要）

同时上线刷题和看画，会带来**归因困难**——失败时不知道是"刷题太难"还是"看画太麻烦"。因此：

- **`打卡` 只由"完成 10 题"触发**，与看画无关；
- **`写画` 独立计数**，不影响打卡。

这样"两条线都做"不会让验证失效：数据上随时能拆开看。

## 2. MVP 范围

### 做（6 个功能块 + 1 个兜底）

| 块 | 内容 |
| --- | --- |
| **① 每日 10 题** | 自动组装、落库、逐题作答、即时反馈与解析、进度跨天保留 |
| **② 错题重推** | 按 1/3/7/15 天重推，**走完全程才出队**（15 天节点答对才出队） |
| **③ 每周一批** | 1 张画（写一句）+ 1 段书籍摘录 + 1 个开放问题 |
| **④ 打卡 + 极简统计条** | 完成后打卡；顶部一行显示连续天数与正确率 |
| **⑤ 主界面（概览 + 导航）** | 粗略预览今天要做什么，两级进入各板块；**鼠标左右移动驱动横排卡片平移**，回车直接落到今日页 |
| **⑥ 推送（内容钩子）** | 每天一次桌面通知，内容是"今天内容里的一个钩子"（如"今天有一道题：德加为什么把画面停在'未完成'"），**不是进度催办**；点通知直接进今日页 |
| **兜底** | 每道题 / 每段内容旁的「标记问题」入口 |

### 不做（明确砍掉）

| 砍掉 | 为什么现在不做 |
| --- | --- |
| 画库回看页 | "写一句"会存下来，但第一版不提供翻看页面（v0.2 补） |
| 题库自由刷题页 | 超出配额的加练，容易让"每日 10 题"这个目标缩小 |
| 笔记 / 收藏 | 摘录只做展示，不做收藏与管理（v0.2 补） |
| 完整统计页 | 只做一个**粗粒度只读**的学习进度页（见 3.3），不做趋势图与薄弱点分析（v0.3 补） |
| 数据导出 | 但**数据结构必须一次做对**，否则后期搬不动 |
| 视觉打磨 | 第一版只要"不难看、能看清"，不做设计感（见 [设计阶段待办](#9-待决事项)） |
| 设置页 | 只保留「标记问题」列表的入口，不做配置界面 |
| 碎片笔记本（内容入口） | 需先有稳定的日常使用习惯才有意义，放 v0.2（需求见 [01-PRD.md](./01-PRD.md) 8.1，技术见 [02-技术方案.md](./02-技术方案.md) 第十二节）；**但右下角入口圆钮第一版就放上去**（只占位、点了提示"v0.2 再做"），**`fragments` 表也第一版就建好**，避免以后改结构 |

### 一个必须说清的取舍

**摘录和开放问题在第一版里只是"展示"，没有留存与回顾**——它们的完整价值要等 v0.2 的笔记功能才成立。现在保留它们成本很低（各存一行数据），但要清楚**它们此刻是"低价值装饰"，不要用它们来判断 MVP 成败**。

---

### 难度定位（2026-10-08 补）

用户是油画专业硕士在读，美术史功底远高于普通爱好者。**题库难度对标各大美院（央美 / 国美 / 清美 / 南艺等）美术史考研真题**，而不是普及读物水平。

- **名词解释 / 简答**：取考研真题里"术语 + 史学理论"一类（如「有意味的形式」「图像证史」「瓦萨里《名人传》的史学价值与局限」），不出「南北宗论」这类通识题。
- **图像辨识**：不停在"判断流派"，要求**判断作者、年代并说明风格依据**。
- **开放论述**：对标考研论述题（如"试论宋代文人画思潮的形成背景、核心主张与对后世的影响"），须有可展开的争议点；不给标准答案，只给参考思路。**并优先取"创作实践"方向**（笔触是否该被看见、完成感从哪来、写生与重构的关系等），贴合其油画创作背景——避免只考纯史学记忆。
- **客观题**：用于巩固基础，但**复习题难度以"当初答错的那道"为准**。
- 题目可标三档：基础 / 进阶 / 挑战，默认进阶。

## 3. 页面结构：主界面 → 今日页 / 学习进度页

第一版**三个页面**（原设想"只有一个今日页"，按 2026-10-07 的决策改为三个）：

```
主界面（概览 + 导航）
   ├─→ 今日页（10 题 + 本周一批）
   └─→ 学习进度页
```

**导航约定（2026-10-08 补 · 硬要求）**

- **任何二级页面都必须有回主界面的入口**，不允许出现"进去了出不来"。
- 草稿里的形态：主界面收起后，**左上角常驻一颗「← 返回主界面」**；进度页自己那条返回保留，两者不重复出现。
- 层级只有**两层**：主界面 ⇄ 二级页。二级页的返回一律回主界面，不做"回上一层"。详见 [01-PRD.md](./01-PRD.md) 第 5 节。

### 3.1 主界面（概览 + 导航）

**只做粗略预览，不做详情；每个板块要两级才能进到内容。** 每天第一次打开时出现。

```
┌──────────────────────────────────────────────┐
│ 10 月 7 日 · 周二                             │
│ 今天想做什么？                                │
├──────────────────────────────────────────────┤
│ ① 今日的题     进度 6/10 · 约 12 分钟    〔展开〕│
│ ② 学习进度     连续 6 天 · 正确率 78%    〔展开〕│
│ ③ 本周一批     春山图 · 摘录 · 一个开放问题 〔展开〕│
└──────────────────────────────────────────────┘
        ↓ 鼠标左右移动 · 卡片横排平移（回车落到今日页）
```

**主界面规则**

- **只显示粗略结论，不显示内容本身**（如"学习进度"只给连续天数和正确率，不给趋势）。
- **两级进入**：第一下点板块 → **就地展开**（预览 + 〔进入〕）；第二下才到内容页。**第一下是"看"，第二下才是"进"。**
- **鼠标左右移动 = 整排概览卡跟着平移**（光标位置映射到横向位移，缓动追赶、不是硬跟手），用来"逛"三个板块。
- **回车 = 直接落到今日页**，不必先选板块——保证"今天只想做题时不被拦路"。
- **每天第一次打开才出现**；当天再打开直接进今日页，摩擦不累积。
- **右下角常驻一颗圆形的「＋」（碎片笔记本入口）** —— 碎片是"随手捡"的动作，入口要任何页面都够得着，不藏进板块里；点开才说明它干什么，平时不写长标签占视线。**v0.1 只做占位**：点一下提示"碎片笔记本 · v0.2 再做"，不带上传流程。**连带一处**：推送通知原来也占右下角，需上移到圆钮上方，两者不重叠。见 [01-PRD.md](./01-PRD.md) 8.1。

### 3.2 今日页

```
┌──────────────────────────────────────────────┐
│ 连续 6 天 · 最长 11 天 · 累计 34 天 · 正确率 78%   │  ← ④ 极简统计条
├──────────────────────────────────────────────┤
│ ① 今日 10 题                        进度 6/10 │
│   第 7 题  〔图像辨识〕              ⚑ 标记问题 │
│   ┌────────────┐                              │
│   │   作品图    │   这幅作品属于哪个流派？       │
│   └────────────┘   ○ A  ○ B  ○ C  ○ D         │
│                              〔提交〕          │
│   （提交后 → 对错 + 解析）                      │
├──────────────────────────────────────────────┤
│ ② 复习题（到期会自动混在上面，并标注"复习"）      │
├──────────────────────────────────────────────┤
│ ③ 本周一批              本周不看也不会催你       │
│   · 每日一画  春山图（局部）                    │
│      〔看图〕 → 写下你的一句话 → 〔存进画库〕     │
│   · 书籍摘录  《隐秘的知识》第四章               │
│      "……"                                    │
│   · 开放问题  如果透视法晚出现 100 年，西方绘画… │
│      〔写下你的想法〕（可留空）                  │
└──────────────────────────────────────────────┘
```

**页面规则**

- **进到今日页后即见**，不需要任何点击就开始做题（上一级是主界面，见 3.1）。
- **每日配额固定 10 题**。隔天打开时，先补完昨天剩余的，再发新题**补足到 10 题**（**不是**再发 10 题），避免题目越拖越多。
- **当天完成 10 题额度 → 打卡成立**（补做的部分计入当天额度）；**被耽误的那一天不补记打卡**。看画与否不影响打卡。
- 本周一批**不设 deadline**，一周内随时可看，未看不记为欠账。
- 错题混在当日题目里出现，但必须**明确标注"复习"**。

### 3.3 学习进度页（第一版只做粗粒度）

- **只读**：连续天数 / 最长连续 / 总完成天数 / 正确率 + 打卡日历（只标"完成 / 未完成"）。
- **不做**趋势图、薄弱知识点分析、标签维度统计 —— 仍留 v0.3。
- 数据全部来自 `GET /api/stats`，**不新增数据表**。

### 3.4 推送（不是页面，是外部触发）

**它补的是这个产品最大的缺口**：网站做得再好，你不打开就什么都不会发生。推送就是那个外部触发点。

**核心规则**

- **每天一次桌面通知**，时间可配（**默认 21:00**）；**到点进程没在跑就跳过，不补发**——补发就是催。
- **文案只做"钩子"，不做"催债"**：取自当天题目或本周画作里的一个**不剧透的引子**。
- **硬防线**：文案里**永远不出现**"你还没做""还差几题""连续要断了"。这三句一出现，就退回催办型了。
- **发通知之前，必须先确保当天内容已生成**——否则点进去还在转圈，钩子当场作废。
- **点通知直接进今日页**；通知里不显示答案、不显示解析。
- 限时间窗（默认 9:00–22:00），不在深夜打扰。
- 电脑没开就没有通知——**接受这个事实，不做跨设备补发**。

**一个已知代价（已告知并接受，2026-10-08）**

推送会**污染主指标的归因**：一旦带上推送，就分不清"是产品留住了我"还是"通知推着我"。这和本节开头"两个信号必须分开记"是同一类问题。

原本的建议是"先跑 8 周无推送版本、不达标再加"，**老叶决定第一版就做**。因此：主指标达标时**不能直接归功于产品本身**；以后若要验证某个改动的价值，需先关掉推送再测。

## 4. 数据最小集

第一版只建这些表（详细字段见 [02-技术方案.md](file:///e:/trae_projects/个人专注力/docs/02-技术方案.md) 第五节）：

| 表 | 第一版是否必建 |
| --- | --- |
| `questions` / `tags` / `question_tags` | 必建（题目与标签是核心） |
| `answers` | 必建（作答记录） |
| `review_queue` | 必建（错题重推） |
| `daily_sessions` | 必建（当日 10 题与进度） |
| `checkins` | 必建（打卡与连续天数） |
| `weekly_batches` | 必建（周批次） |
| `artworks` / `artwork_notes` | 必建（画与"写一句"） |
| `excerpts` / `open_questions` | 必建（只存只展示） |
| `flagged_items` | 必建（标记问题兜底） |
| `notes` | **不建**，v0.2 再补 |
| `settings` | 不必建，第一版把参数写进配置文件即可 |

> **硬约束**：虽然导出功能砍了，但**字段要一次设计对**（尤其是标签、复习间隔、连对计数），否则 v0.2 迁移代价很大。

## 5. 验收清单

可直接当测试用例用。

**页面与导航**

- [ ] 每天**第一次**打开落到主界面；当天再打开**直接进今日页**
- [ ] 主界面三个板块都能"第一下就地展开预览、第二下进入内容页"
- [ ] 主界面**只显示粗略结论**，不泄露题目内容与解析
- [ ] 从主界面**回车**直接落到今日页；鼠标左右移动时整排卡片跟着平移（缓动追赶，不硬跟手）
- [ ] 学习进度页只读：能看连续 / 最长 / 总天数 / 正确率与打卡日历，且**没有趋势图**
- [ ] **任何二级页都能回主界面**：今日页 / 本周一批 / 学习进度页都有一条「← 返回主界面」，点了回到主界面——**不允许出现"进去了出不来"**
- [ ] 右下角常驻圆形「＋」（碎片入口）：第一版点了**只提示"v0.2 再做"**，不弹上传界面；它和推送通知不重叠

**每日 10 题**

- [ ] 进到今日页后 10 道题自动展示，无需再点击
- [ ] 中外美术史混合出现，不按时间线排序
- [ ] 题型受上限约束：论述 ≤ 1、名词解释 ≤ 2、图像辨识 ≤ 2，其余为客观题
- [ ] 题目生成后落库并打上细标签
- [ ] 同一天重复打开，题目不重新生成、内容不变
- [ ] 新题与库内已有题按内容指纹去重

**作答与反馈**

- [ ] 客观题提交后立即显示对错
- [ ] 名词解释 / 简答提交后可对照参考答案并自评
- [ ] 图像辨识题展示作品图并要求判断
- [ ] 开放论述题提交后给出参考思路
- [ ] 每题作答后显示解析

**错题重推**

- [ ] 答错的题进入队列，1 天后重新出现，并标注"复习"
- [ ] 复习答对 → 连对计数 +1，间隔推进 1 → 3 → 7 → 15 天
- [ ] 复习答错 → 连对计数归零，间隔退回 1 天
- [ ] **在 15 天节点答对才出队**（走完全程），此后不再出现

**进度与打卡**

- [ ] 未做完 10 题，隔天打开先补完剩余，再发新题**补足到 10 题**（当天总数仍是 10 题，**不堆积**）
- [ ] 当天完成 10 题额度后显示"今日已完成"并打卡（补做的部分计入当天额度）
- [ ] 被耽误的那一天**不补记打卡**
- [ ] 打卡状态持久保存，刷新不丢失
- [ ] 跨天未打卡：连续天数归零，但"最长连续"和"总完成天数"保留
- [ ] 看画与否**不影响**打卡

**每周一批**

- [ ] 每 7 天（**滚动周期，非自然周**）生成 1 张画 + 1 段摘录 + 1 个开放问题
- [ ] 画作提供输入框，写下的内容存入画库
- [ ] 未写可跳过，但标记为"未写"
- [ ] 整周随时可看，未看不记为欠账
- [ ] 图片下载到本机缓存，不使用外链直显

**兜底与异常**

- [ ] 每道题、每段内容旁有「标记问题」入口，可附一句说明
- [ ] 已标记的题不再出现在每日题中
- [ ] AI 生成失败时有明确提示与重试，**不白屏**
- [ ] 密钥只存在本机 `.env`

**推送**

- [ ] 每天到点弹一条**桌面通知**，内容是"今天内容里的一个钩子"，**不是进度催办**
- [ ] 通知文案中**不出现**"你还没做 / 还差几题 / 连续要断了"
- [ ] **点通知直接进今日页**；通知里不显示答案与解析
- [ ] 发通知前当天内容已生成好——点进去**不会**看到加载转圈
- [ ] 到点时进程没在跑就**跳过、不补发**；只在 9:00–22:00 时间窗内发
- [ ] 同一天不重复发第二条

## 6. MVP 的失败判据

**什么情况下判定"最小版本不成立"**（提前定好，避免事后自我安慰）：

| 判据 | 阈值 | 说明 |
| --- | --- | --- |
| 习惯没立住 | 4 周内达标周数 < 50% | **主判据**。先减量（每日 10 → 6 题），再判断 |
| 内容不可信 | 明显错误的题累计 ≥ 5 道且未处理 | 优先解决生成策略，而不是继续堆量 |
| 负担过重 | 单日完成时长 > 20 分钟 | 说明内容量或题型配比失控 |
| 画面失效 | 画作"已写"比例 < 30% | 说明看画环节被跳过 → 检查是不是太麻烦 |

**任一主判据触发，先减量再判断，不要直接放弃。**

## 9. 决策记录与待决事项

### 已决（2026-10-07）

| 事项 | 结论 | 理由 |
| --- | --- | --- |
| 隔天补完是否算当天打卡 | **算当天的额度**；被耽误的那天不补记 | 不惩罚"某天忙"，也不让补做白做 |
| 每日配额是否会因补做而膨胀 | **不会**，永远 10 题（补完剩余后只"补足到 10"） | 防止"越拖越多"直接导致放弃——这是本项目最大风险 |
| "每周一批"的周期 | **滚动 7 天**，不是自然周 | 自然周会在周一重置，产生隐性 deadline 焦虑，违背"不设 deadline"的设计意图 |
| 开放问题是否保留 | **保留**，但标记为观察项 | 2 周后看作答率，< 20% 就降到 v0.2 |
| 主界面的定位 | **概览 + 导航**，只做粗略预览，每个板块两级进入 | 老叶 2026-10-07 明确；第一版不做成功能齐全的首页 |
| 主界面出现频率 | **每天第一次打开才出现**，当天再打开直接进今日页 | 保住仪式感，又不在同一天反复收"过路费"（主指标是"每周 ≥ 3 天完成 10 题"） |
| 学习进度页的范围 | **只做粗粒度只读页**（`/api/stats` 已有数据） | 不让"看统计"挤占 MVP 要验证的东西（习惯是否立得住） |
