## 1. 产品摘要

我们为**美术专业出身、工作后没时间系统复盘的老叶**，做一个**只给自己用的美术史复盘网站**，解决「艺术史知识在流失、审美缺乏持续输入、没有固定输入节奏」这三个问题。

网站**每天给 10 道题**（中国美术史 + 外国美术史，四种题型随机但设上限），**每周给一批**高质量内容：一张画（看完要写一句话）、一段书籍原文摘录、一个开放问题。答错的题按 **1 / 3 / 7 / 15 天**的遗忘曲线自动重推，所有数据沉淀为**统计、打卡、画库、笔记**。

预期结果是：**让"每天复习美术史"这件事真的能坚持下来**，而不是做出来三天就废。

## 2. 问题陈述

### 谁有这个问题？

**老叶本人**——美术专业出身，热爱看画，现在从事产品工作。

### 问题是什么？

1. 上学时系统学过的中美史、外美史，工作后**没有时间定期回看**，知识在持续流失。
2. 作为专业出身的人，对"好看"的判断力需要**长期、有质量地喂养**，现在只能零散刷图，不成体系。
3. 想复习的时候，**没有现成的题库和素材**，也**没有固定的节奏**，全凭一时兴起。

### 为什么痛苦？

- **个人层面**：专业能力退化的焦虑——学美术的人丢掉美术史和眼力，是一种"身份流失"。
- **机会成本**：输出内容、看展览、聊艺术时，知识调不出来；审美判断变得依赖直觉而非积淀。
- **现有工具都不对路**：通用背单词软件没有美术史内容；博物馆 App 是"逛"不是"复练"；教材是"读"不是"练"。

### 证据

- **本人自述（需求方原话）**："我本身是学美术的，我喜欢看一些画作。但是由于我现在工作之类的，我其实是没有那么多时间去定期的复盘我脑子里面的知识的，就是……也包括我自己一些美感的一些积累。"
- **行为信号**：明确表达了"理想形态"（每天 10 题 + 1 张画 + 开放问题 + 书籍摘要），说明这不是模糊愿望，而是有具体画面。
- **专业要求信号**：明确要求"这一块要做得专业一点，毕竟我其实是专业人士"——对内容质量有门槛。
- 🔵 **待补**：没有量化的基线数据（例如"现在多久看一次画""上次系统复习是什么时候"）。个人项目可接受，不作为阻塞项。

## 3. 目标用户

### 主用户（唯一用户）

- **Name**：老叶
- **Role**：产品经理，美术专业背景
- **Context**：工作时间长，可支配的自我提升时间碎片化；对美术史有专业底子，不是零基础；能识别内容对错，容忍不了业余内容
- **Goals**：
  - 让美术史知识不继续流失，甚至比学生时代更牢
  - 通过持续看画 + 写字，维持并提升审美判断力
  - 每天花**不超过 15 分钟**就能完成当日份
- **Pain points**：没时间、没题库、没节奏；通用工具没有专业内容
- **Current behaviour**：零散刷图、偶尔翻书，没有固定频率

### 次用户

- 无。**明确不做多用户**（见第 8 节）。

### 要完成的任务（JTBD）

- **功能性任务**：每天用 10 分钟，把一个具体的艺术史知识点从"学过"变成"记得"。
- **功能性任务**：每周认真看一张好画，并写下自己的判断，形成可回看的审美档案。
- **情绪性任务**：不因为"又没复习"而持续愧疚；打开网站就有一个小而确定的完成感。
- **社会性任务**：在和同行、客户、朋友聊艺术时，能随时调出准确的史实和判断，维持"专业人士"的身份感。

## 4. 战略背景（按个人项目改写）

### 个人目标

- **核心目标**：把"复习美术史"从一个"想做但总也不做"的愿望，变成一个**每天自动发生**的固定动作。
- **关联目标**：为将来的内容输出（写作、分享、作品）积累可调用的知识库和审美素材。

> 本节不适用商业 OKR、TAM/SAM/SOM、竞品分析——本项目为单人自用，无商业目标。

### 替代方案（不做的对手是谁）

| 替代方案 | 能满足 | 不能满足 |
| --- | --- | --- |
| 通用背题 / 记忆 App | 间隔复习机制 | 没有美术史专业内容 |
| 博物馆 / 艺术类 App | 看画、看展览 | 不做知识复练，无错题与统计 |
| 教材 / 画册 | 内容权威 | 不是"练"，无法追踪掌握程度 |
| 自己整理笔记 | 完全可控 | 无法持续，整理本身就很耗时间 |

**结论**：现有方案要么有机制没内容，要么有内容没机制。本项目要做的是**把"专业内容"和"复盘机制"合到一个只服务自己的系统里**。

### 为什么是现在？

1. 工作后知识流失的焦虑已经具体化，需求是真实的。
2. AI 已能按标签批量生成结构化题目与讲解，**内容供给这个过去的瓶颈第一次变得可行**。
3. 明确等到"以后有时间"再做，等于永远不做——所以现在把它建成一个**每天会自动推内容**的系统。

## 5. 方案概述

### 方案描述

这是一个**只在本机运行的网站**（前端 + 本机小后端，数据存本机文件），打开即用，无需登录。

打开网站进入**今日页**：系统按你的标签体系，实时生成并落库 10 道题（中国美术史 + 外国美术史混合，题型随机但受上限约束），逐题作答并即时看到解析。答错的题进入复习队列，按 **1 / 3 / 7 / 15 天**的间隔重新出现。全部完成后打卡。

**每周更新一批**内容：一张画（来源为博物馆开放素材），你看完必须写一句话，这句话会存进画库；一段书籍原文摘录（如大卫·霍克尼《隐秘的知识》）；一个开放问题。这一批内容**不绑定具体哪天**，一周内随时可看，不设 deadline，避免"欠账感"。

所有内容（题、画、摘录、你写的字）都**落库并打标签**，形成会随时间增长的私人题库与审美档案。因为 AI 生成的内容会有硬伤，设置页提供一个**「标记问题」**入口，把可疑内容攒起来，供以后集中审核。

### 关键功能

1. **每日 10 题引擎**：按标签体系生成、落库、去重；题型随机但设上限（论述 ≤ 1、名词 ≤ 2、图像辨识 ≤ 2）。
2. **四种题型**：客观题（选择/填空）、名词解释/简答、图像辨识题、开放论述题。**难度对标各大美院美术史考研真题**（用户为油画专业硕士在读，通识题太浅）。
3. **错题复习**：按 1/3/7/15 天遗忘曲线重推。
4. **每周内容批次**：每日一画（可写一句）、书籍原文摘录、开放问题，一周一批随时可看。
5. **画库**：看过的画 + 当时写下的话，可回看，形成审美档案。
6. **细标签体系**：中外 × 时期 × 流派/门类 × 作者/作品/技法。
7. **统计与打卡**：连续天数、正确率、题型分布、薄弱点。
8. **笔记与收藏**：攒下的摘录与感想。
9. **标记问题**：把可疑的 AI 生成内容攒起来，供后置审核。
10. **数据可备份**：本机存储 + 一键导出。

### 核心流程

**每日**
```
打开网站 → 今日页生成 10 题
  → 逐题作答 → 即时反馈 + 解析
  → 完成打卡 → 错题进入复习队列
```

**每周**
```
一批内容更新（随时可看，不设 deadline）
  → 看 1 张画 → 写一句话 → 存入画库
  → 读 1 段原文摘录 → 可收藏
  → 1 个开放问题 → 可选作答
```

### 页面结构

| 页面 | 作用 |
| --- | --- |
| 今日 | 当日 10 题 + 本周的画 / 摘录 / 开放问题 + 完成状态 |
| 题库 / 练习 | 按标签自由刷题（超出每日配额的加练） |
| 画库 | 看过的画 + 自己写的话 |
| 笔记 / 收藏 | 攒下的片段与感想 |
| 统计 / 打卡 | 连续天数、正确率、题型分布、薄弱点 |
| 设置 | 内容偏好、每日配额、标记问题、数据管理 |

**导航约定（2026-10-08 补）**

- **任何二级页面都必须有回主界面的入口**，不允许出现"进去了出不来"。这是硬要求，不是可选项。
- 层级只做**两层**：**主界面 ⇄ 二级页**（今日页 / 学习进度页 / 以后的画库、题库等）。不做三层及以上，也不做"二级页之间互相跳"的迷宫。
- 主界面是唯一的顶层；二级页的返回一律回到主界面，而不是"回上一层"。

## 6. 成功指标

> 本项目无商业指标。以下为**个人使用指标**——衡量的是"这个习惯有没有真的建立起来"，而不是收入或增长。

### 主指标

**每周至少完成 3 天的比例**（"10 题打卡 ≥ 3 天"的周数 / 总周数）

- **当前基线**：0（尚无系统，过去无固定复习行为）
- **目标**：上线后第 2 个月起，**≥ 70% 的周达标**
- **衡量时点**：上线后连续观察 8 周

> 说明：这是"习惯是否成立"的代理指标。若这个数上不去，说明产品本身有问题，其他指标都不重要。

### 次指标

- **单日完成时长**：≤ 15 分钟（超过说明内容量失控）
- **错题重推正确率**：重复出现的题，第二次做对比例 ≥ 60%
- **画库累计**：8 周内 ≥ 8 张画 + 8 句话（每周一批是否真在看）
- **题库存量**：8 周内累计 ≥ 400 道已落库题目

### 护栏指标

- **不想打开的冲动**：若出现"今天不想开"的次数每周 ≥ 3 次，必须减量——宁可降低强度，不可让产品变成负担。
- **专业信任度**：若明显错误的题目累计 ≥ 5 道且未处理，说明内容质量已跌破底线，需优先解决而不是继续堆量。

## 7. 用户故事与需求

### 史诗假设

> 我们相信，为一个美术专业出身、时间碎片化的人做一个**每天 10 题 + 每周一批内容**的美术史复盘网站，能让"复习美术史"这个习惯真正建立起来——因为当前的问题不是没兴趣，而是**没内容、没节奏、没机制**。我们将用上线后 8 周内「每周至少 3 天打卡」的比例是否达到 70% 来验证。

### 用户故事

**Story 1：每日 10 题自动出现**

作为老叶，我希望打开网站就看到今天的 10 道题，这样我不用先想"今天做点什么"。

验收标准：

- [ ] 打开网站默认进入今日页，10 道题自动展示，无需任何点击
- [ ] 题目涵盖中国美术史与外国美术史，**混合出现**（不按时间线顺序）
- [ ] 题型为四种之一，但受上限约束：论述 ≤ 1、名词解释 ≤ 2、图像辨识 ≤ 2，其余为客观题
- [ ] 生成后的题目**落库并打上细标签**（中外 / 时期 / 流派 / 作者 / 作品 / 技法）
- [ ] 同一天重复打开，题目不重复生成、不变化

**Story 2：逐题作答与即时反馈**

作为老叶，我希望做完一题马上知道对错和解析，这样我能当场纠错。

验收标准：

- [ ] 客观题：选择 / 填空，提交后立即显示对错
- [ ] 名词解释 / 简答：提交后可对照参考答案，并可自评"对 / 错"
- [ ] 图像辨识题：显示作品图，要求判断作者 / 年代 / 流派等
- [ ] 开放论述题：无标准答案，提交后给出参考思路
- [ ] 每题作答后显示解析（含关键史实点）

**Story 3：错题按遗忘曲线重推**

作为老叶，我希望答错的题在合适的时间再出现，这样我真的能记住而不是做过就忘。

验收标准：

- [ ] 答错的题进入复习队列，按 1 / 3 / 7 / 15 天间隔重新出现
- [ ] 复习题可与当日新题混合出现，并明确标识"这是复习题"
- [ ] 答对时按 1 → 3 → 7 → 15 天推进间隔；**在 15 天节点答对才出队**（走完全程，等价于连对 4 次），不再出现
- [ ] 答错则连对计数归零，间隔退回 1 天

**Story 4：完成打卡**

作为老叶，我希望做完 10 题就有个完成状态，这样我有确定的收尾感。

验收标准：

- [ ] 10 题全部作答后，今日页显示"今日已完成"
- [ ] 记录当日完成时间，可写入连续打卡天数
- [ ] 打卡状态持久保存，刷新不丢失

**Story 5：每周一批内容**

作为老叶，我希望每周有一批新内容（画 / 摘录 / 开放问题），这样我不只是刷题。

验收标准：

- [ ] 每周生成一批：1 张画 + 1 段书籍原文摘录 + 1 个开放问题
- [ ] 内容展示在今日页的一个独立区块，**不设完成 deadline**
- [ ] 一周内随时可看，未看完不顺延为"欠账"
- [ ] 图片来自博物馆开放素材，本地缓存图片以免外链失效

**Story 6：看画写一句 → 进画库**

作为老叶，我希望看完画必须写一句话，且这句话能存下来，这样我的审美判断会累积成档案。

验收标准：

- [ ] 画作展示后提供输入框，提示写一句自己的判断
- [ ] 写下的内容存入画库，与作品绑定
- [ ] 画库可浏览历史，**再次看到同一张画时能回看当时写的话**
- [ ] 未写也可跳过（不强制阻塞），但会标记为"未写"

**Story 7：统计与打卡页**

作为老叶，我希望看到自己的坚持数据和薄弱点，这样我知道该补哪里。

验收标准：

- [ ] 显示连续打卡天数、总完成天数
- [ ] 显示正确率（总体 / 按题型）
- [ ] 显示薄弱点（正确率最低的标签，如"明清"或"印象派"）
- [ ] 显示画库累计条数、笔记累计条数

**Story 8：笔记与收藏**

作为老叶，我希望把摘录和感想收藏起来，以后能翻。

验收标准：

- [ ] 书籍摘录可一键收藏
- [ ] 自己写的画作感想自动进入笔记体系
- [ ] 支持按时间浏览、按内容搜索

**Story 9：标记可疑内容**

作为老叶，我希望遇到 AI 写错的题能标记一下，这样以后能集中审核，不至于信任崩塌。

验收标准：

- [ ] 每道题、每段内容旁有"标记问题"入口
- [ ] 标记后可追加一句说明（可选）
- [ ] 标记内容汇总到设置页的待审核列表
- [ ] 已标记的题不再出现在每日题中

**Story 10：数据备份**

作为老叶，我希望数据能导出备份，这样不担心丢。

验收标准：

- [ ] 提供一键导出（含题目、作答记录、画库、笔记、打卡）
- [ ] 导出为可读文件格式，存本机
- [ ] 数据存本机文件，非浏览器缓存

### 约束与边界情况

- **技术约束**：前端 + 本机小后端；数据存本机文件；无登录、无多用户；图片需本地缓存防外链失效。
- **内容约束**：AI 实时生成，准确性不由人工前置把关（已确认接受此风险），靠"标记问题"后置补救。
- **边界情况**：
  - 当天生成失败 / 网络异常 → 需有失败提示与重试，不可白屏
  - 同一道题重复生成 → 落库时需去重
  - 某标签题量不足 → 生成时需放宽或提示
  - 一天做不完 10 题 → **保留进度**，隔天先补完剩余，再发新题**补足到 10 题**（配额固定，不堆积）
  - 跨天未打卡 → 连续天数**不清零**，但"当前连续"归零；"最长连续 / 总完成天数"永久保留

## 8. 不在本次范围内

**明确不做：**

- **多用户 / 账号体系** — 只服务本人，无登录、无权限、无数据隔离
- **社交与分享** — 不公开发布、不导出为分享页
- **移动端 App** — 先做网页，手机浏览器能打开即可，不做原生 App
- **人工前置审核流程** — 内容先实时生成，审核后置（用"标记问题"承接）
- **商业化 / 付费墙** — 无商业目标
- **内容社区 / 公共题库** — 题库是私人资产，不共享

**未来可能考虑：**

- 手机端体验优化
- 多设备同步（需要后端上云）
- 从"做题"扩展到"看图谱系 / 时间线可视化"
- 把标记出的问题集中审核后，反哺题库质量
- **碎片笔记本（内容入口）** —— 见 8.1

### 8.1 碎片笔记本（v0.2 候选，2026-10-08 讨论成型）

**问题**：现在的内容都是"系统给的"（AI 生成 + 每周一批给一张画），缺了"我自己给"的那一路——平时在小红书、微信刷到的好东西，看过就散了。

**做法**：给一个上传窗口。截图丢进来 → **AI 读图生成一句摘要 + 几个标签**（让碎片可搜）→ 存进"碎片池"。

**定位：起点，不是终点。** 碎片是原料，出口有两个：

- 被挑进**每周一批**（那周的画可以来自你自己攒的，而不是博物馆库随机挑）
- 作为**出题素材**喂给 AI

**四条已定的设计约束**：

1. **出口是"可选消费"，不是"待办清单"** —— 池子里有合适的就用，没有就照常走原流程。碎片不欠账、不清零、不催。
2. **读图分两类处理** —— 图为主（一幅画的截图）走画面描述（作者 / 年代 / 题材 / 可辨识特征）；字为主（讲画的文字、评论）走 **OCR 抽文字**。混在一起两头不讨好。
3. **入口先做电脑那条**（网页粘贴 / 拖拽）；手机走"同一 WiFi 访问本机站点 + 相册选图"，不做 App。两条共用同一个上传接口。
4. **入口形态：主界面右下角常驻的一颗圆形按钮（＋）**。碎片是"随手捡"的动作——在小红书看到一张画，想立刻丢进来，入口就必须**任何页面都够得着**，不能藏进某个板块的二级页里。点开才说明它是干什么的（自己不写长标签，免得天天占着视线）。
   - 第一版（v0.1）只做**入口占位**：点一下提示"碎片笔记本 · v0.2 再做"，不带上传流程。
   - **连带一处**：右下角已被"推送通知"占用，通知需上移到圆按钮上方，避免叠在一起。

**本版不做**：碎片不删，按时间沉底。

**风险**：收集箱变成垃圾桶。靠第 1 条约束化解；若出口实际用不上，说明"起点"定位判断错了，退回"终点"重估。

## 9. 依赖与风险

### 依赖

- **技术**（已定选型）：
  | 零件 | 选型 | 理由 |
  | --- | --- | --- |
  | 前端 | **React + Vite + TypeScript** | 主流、组件化；页面多、后续易扩展与接手 |
  | 后端 | **Node.js** | 与前端同一门语言，只装一套运行环境 |
  | 存储 | **SQLite**（本机单文件） | 支持标签查询、错题队列与统计 |
  | 运行方式 | 本机启动 → 浏览器打开 | 双击启动脚本即可；用户只需安装 Node.js |
- **外部**：AI 生成能力（**国内直连服务商**，用于出题 / 讲解 / 摘录）；图片开放素材（**境内外都取**：大都会 Met · 芝加哥艺术馆 · 台北故宫开放资料，已可覆盖中外藏品）
- **设计**：视觉方案（设计阶段先出多个方向供选择，见第 10 节）
- **内容**：首批题目的生成策略与覆盖范围；书籍原文摘录的来源（需本人提供或指定书目）

### 风险与应对

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| **坚持不下来（最大风险）** | 做出来三天就不打开，产品价值归零 | 已通过设计降负担：每日仅 10 题且设题型上限、周内容不设 deadline；用主指标持续观察，不达标先减量 |
| **AI 内容出错** | 年代、作者归属、流派等硬事实错误，专业用户一眼识破，摧毁信任 | 设置"标记问题"入口后置审核；护栏指标监控错误累计数 |
| **内容重复 / 枯竭** | 每天生成，很快出现重复题 | 落库去重；按标签控制出题分布 |
| **图片外链失效 / 版权** | 开放素材链接失效或授权变动 | 用开放授权资源；图片本地缓存 |
| **数据丢失** | 只存本机，硬盘故障即全失 | 本机文件存储 + 一键导出备份 |
| **生成延迟 / 成本** | 每次打开都实时生成，等待久 | 每日首次生成后落库复用；同一天不重复生成 |
| **内容不成体系** | 随机抽题导致知识点零散 | 题库按细标签建设、按标签均衡出题 |
| **摘录版权** | 原文摘录理论上涉及版权 | 仅个人自用、不公开传播，已确认接受 |
