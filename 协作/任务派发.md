## 3. 接口清单（前端只用 1–11；12/13 属 v0.2，不做；14 是后端验收用）

| # | 方法 | 路径 | 用途 |
| --- | --- | --- | --- |
| 1 | GET | `/api/health` | 探活 |
| 2 | GET | `/api/today` | 今日 10 题 + 进度 + 是否打卡 |
| 3 | POST | `/api/answers` | 交卷、拿判定与解析 |
| 4 | GET | `/api/stats` | 连续 / 最长 / 总天数 / 正确率 + 打卡日历 |
| 5 | GET | `/api/weekly` | 本周一批（画 / 摘录 / 开放问题） |

| 9 | GET | `/api/images/{filename}` | 取本地缓存图（图片二进制） |

| 11 | GET | `/api/stats` 扩展 | 同一个接口，多了 `calendar[]`（最近 30 天打卡） |

### `/api/today` 的 `questions[]` 单项字段

```json
{
  "id": 12,
  "type": "objective",
  "stem": "题干文字",
  "options": ["A 选项", "B 选项", "C 选项", "D 选项"],
  "difficulty": "进阶",
  "image_url": "/api/images/met-437881.jpg",
  "is_review": false,
  "tags": ["宋", "文人画"]
}
```

`type` 四个值之一：`objective`（客观题）/ `term`（名词解释）/ `image`（图像辨识）/ `essay`（开放论述）。
`term` 与 `essay` 的 `options` 为 `null`。
`image_url` 可能为 `null`（图还没下好），前端要能容错。
`is_review: true` 是复习题，要跟新题在视觉上明确区分。

### `POST /api/answers` 的请求与响应

请求：`{question_id, user_answer, self_grade?}`——**四种题型都必须带 `user_answer`**（先交卷才换得到判定与参考答案）。

响应：`{correct, explanation, reference_answer, ai_comment, ai_errors, next_review_at}`

## 4. 必须守住的几条规则（做错会返工）

1. **`/api/today` 绝不返回答案和解析。** 答案只在交卷后（`/api/answers`）给，前端别指望提前拿到。
2. **`/api/today` 是同步阻塞的。** 首次打开后端要凑齐 10 题（可能真调 AI，几十秒才回），前端**全程 loading、不要轮询**。当天第二次打开因已落库，是秒开。
3. **主观题提交要等十几秒。** 名词与论述题是后端**同步等一次 AI 判分**，前端**必须给 loading，不要轮询**，别当成接口卡死。
4. **`correct` 为 `null`** 表示 AI 没判上（网络问题等），这时界面直接**让用户自己定**对错，不要报错。
5. **不认可 AI 判定**：带 `self_grade`（`true`/`false`）**再提交一次同一题**即为改判。客观题不接受 `self_grade`（会返回 400）。
6. **`notice` 字段**：非 `null` 时是给人看的一句话提示（如 AI 暂时不可用），**照常显示手头的题，不要白屏**。
7. **图片走 `/api/images/{filename}`**，直接用 `image_url` 即可，断网也能显示。
8. **前端不算连续天数、不算遗忘曲线。** 一律读 `/api/stats`，别自己算，否则数字会跟后端对不上。
9. **文案硬防线**：界面上不出现"你还没做 / 还差几题 / 连续要断了"这类催办话。
10. **前端不直连 AI、不读数据库文件**，一律走后端接口。

## 5. 已定事项（不用再问，直接照做）

- **视觉**：B · 夜馆（暗色）作为默认皮肤，设计稿已就绪。
- **主界面交互**：鼠标左右移动驱动整排卡片横移（`pointermove` + rAF 缓动追赶，`translate3d`），**回车**落到今日页。
- **两级进入**：第一下就地展开预览 +〔进入〕，第二下才路由到内容页。
- **返回导航硬要求**：任何二级页（今日页 / 本周一批 / 进度页）都必须有常驻「← 返回主界面」，不允许"进去了出不来"；层级只做主界面 ⇄ 二级页两层。
- **右下角碎片圆钮**：常驻，v0.1 **只占位**，点了横向展开提示"碎片笔记本 · v0.2 再做"，**不带上传流程**；推送通知已上移到圆钮上方避免重叠。
- **当天第二次打开跳过主界面**，直接进今日页。
- **推送标题**：`日拱一卒`；点通知打开今日页（`http://localhost:5178/`）。

| **T1 骨架** | M0 | Vite + React + TS；三个路由（主界面 / 今日页 / 进度页），先实现今日页，另两个占位；主题变量（最小样式） | 能打开今日页空壳，并把 `/api/health` 的结果显示出来 |

| **T3 答题交互与反馈** | M2 | 选项 / 填空 / 自评；提交调 `/api/answers`（主观题要 loading）；展示对错 / 解析 / 参考答案 / AI 点评与硬错误；不认可带 `self_grade` 改判（`correct` 为 `null` 时让用户自己定）；进度 x/10；切真实接口 | 四种题型都能提交并看到反馈；答完 10 题显示 10/10 |

| **T5 统计条与完成态** | M4 | 顶部一行展示连续 / 最长 / 总天数 / 正确率（读 `/api/stats`）；完成 10 题后切"今日已完成" | 数字与后端一致；完成后状态正确切换且刷新仍保持 |
| **T6 周批次区块** | M5 | 画作展示 + "写一句"输入与保存；摘录展示；开放问题输入（可留空）；标注"本周不看也不会催你" | 写一句能保存、刷新后还在；留空也能正常切换 |

| **T8 主界面** | M7 | 三个概览卡横排、每张右侧配一张名画（本地缓存图）、只显示粗略结论；两级进入；鼠标左右移动驱动横排平移；回车进今日页；当天已打开则重定向。一并做：统一返回导航 + 右下角碎片圆钮 | 鼠标左右移动整排跟着平移（缓动追赶、不硬跟手）；回车能进今日页；三个板块都两级进入；当天第二次打开跳过主界面；从任何二级页都能一键回主界面；碎片圆钮只提示 v0.2 |
